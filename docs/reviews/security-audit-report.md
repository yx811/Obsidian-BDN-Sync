# BDNSync 安全审计报告

**审计范围**：架构 / 网络配置 / 身份认证 / 数据存储 / 接口调用 / 输入校验 / 敏感信息处理
**代码版本**：v1.0.2（含 v1.0.1 全量审计）

---

## 1. 安全架构

```
┌─────────────────┐      ┌──────────────────┐      ┌─────────────────────┐
│  Obsidian Vault │◄────►│  BDNSync Plugin  │◄────►│  百度网盘 API        │
│  (本地文件/索引) │      │  (engine/adapter) │      │  (cookie/openapi)   │
└─────────────────┘      └──────────────────┘      └─────────────────────┘
        ▲                        ▲                          ▲
   本地信任边界            插件进程内（Obsidian）      网络边界（HTTPS）
```

- **数据类型**：用户 Markdown/附件、网盘凭证（BDUSS/Token/SecretKey）、加密密码
- **认证双模式**：Cookie 模式（BDUSS/STOKEN，仅下载/列表/删除）、OpenAPI 模式（设备码 OAuth，全功能含上传）
- **信任边界**：本地 vault ↔ 插件（同进程）；插件 ↔ 百度网盘（HTTPS）；插件配置持久化

## 2. 风险发现与处置

### 🔴 设置导入任意字段覆盖（Mass-Assignment）
- **风险**：用户粘贴的任意 JSON 会被整体合并进设置，可能注入非预期字段篡改同步行为，触发大规模误删或路径越界
- **修复**：新增白名单校验函数，仅接受已知配置键，并对枚举值、数值范围、字符串长度逐一验证；`deviceId` 永不从导入覆盖
- **状态**：✅ 已修复

### 🔴 凭证泄露到日志与错误信息
- **风险**：上传 URL 中嵌入 `access_token`，请求失败时完整 token 可能进入错误详情或持久化日志，被窃取网盘访问权
- **修复**：统一脱敏工具，在网络异常、上传错误中对 `access_token`/`BDUSS`/`STOKEN`/`refresh_token`/`client_secret`/`secretKey` 自动脱敏为 `<redacted>`
- **状态**：✅ 已修复

### 🔴 凭证明文持久化（设计约束）
- **风险**：网盘凭证以明文序列化进插件配置文件，设备被入侵或备份泄露会直接暴露网盘访问权
- **缓解措施**：
  1. 所有凭证输入框均以 `type='password'` 掩码显示
  2. 导出设置到剪贴板时自动脱敏所有凭证字段
  3. 日志中不打印凭证（已由上方修复覆盖）
- **后续建议**：实现设备绑定密钥的信封加密，对敏感字段做 AES-GCM 加密后再序列化
- **状态**：🟡 部分缓解 + 文档化

### 🟠 下载无元数据篡改防护
- **风险**：下载时直接全量读入内存，若服务端元数据被篡改（小于实际内容），可能撑爆本地内存
- **修复**：在下载完成后增加实际字节 vs 声明大小的 1.1 倍上限校验，超出则拒绝下载；同时保留哈希完整性校验
- **状态**：✅ 已修复

### 🟠 远程文件名/XSS 防护
- **风险**：远程文件名来自服务端，含 HTML 特殊字符时可能造成 DOM XSS
- **评估**：路径规范化防穿越已落实；Obsidian 组件默认走 `textContent`（非 `innerHTML`）。项目中确有 4 处 `innerHTML` 使用：`components.ts` 的 2 处为内置静态 SVG 图标 / resize grip（白名单，无远程数据）；`sync-log-view.ts` 的 2 处渲染日志 `message` / `path`（可能含远程文件名），但均先经 `highlight()` 做 HTML 转义（`& < > "`），仅对转义后的文本包裹 `<mark>` 高亮，不存在注入点。日志与通知用字符串拼接，无 XSS 风险
- **状态**：✅ 已确认安全（含转义说明）

### 🟢 设备 ID 随机性（已加固）
- **风险（历史）**：曾使用 `Math.random` 生成设备 ID，非密码学随机
- **当前实现**：`genDeviceId()` 优先使用 `crypto.randomUUID()`（密码学随机），仅在不可用时回退到 `randomId()`（`Math.random`）；仅作设备标识，冲突影响极小
- **状态**：✅ 已加固（主流路径为密码学随机）

## 3. 已确认的安全实践

| 实践 | 说明 |
|------|------|
| AES-256-GCM + PBKDF2-SHA256（10 万轮） | 端到端加密，每文件随机 IV |
| 沙箱根下界保护 | 永不在网盘根目录之上创建，防越界 |
| 路径规范化防穿越 | 统一正斜杠、合并重复、去尾斜杠 |
| 下载大小上限 | 防止超大文件 |
| QPS 节流 + 瞬态重试 | 限流退避，尊重服务端限流 |
| 鉴权错误快速失败 | 401/服务错误不重试，防枚举 |
| 断点续传脏数据校验 | TTL + MD5 一致性校验，防脏续传 |
| 远程索引分片容错 | 单分片损坏不影响其余 |
| 凭据信封加密（AES-256-GCM `enc::`） | 落盘前加密，主密钥隔离于 `localStorage` |
