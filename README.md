## 项目简介

**BDNSync** 是一个开源的 [Obsidian](https://obsidian.md) 第三方插件，用于把本地笔记库（vault）与[百度网盘](https://pan.baidu.com)双向同步，提供类似 WPS 云文档的"云端协同"体验。

它的目标是解决以下痛点：

- **多设备协同**：在桌面端、移动端之间保持笔记一致，无需手动导出导入。
- **数据安全**：支持 AES-256-GCM 端到端加密，百度网盘无法读取明文；凭证落盘前信封加密。
- **冲突无忧**：以"本地 / 云端 / 上次同步锚点"三向对比，文本自动 `diff3` 合并，二进制自动分叉保留。
- **误删可救**：删除以"墓碑 + 宽限期"同步，宽限期内可恢复；强制方向同步前自动生成整库快照。
- **稳定可靠**：断点续传、失败指数退避重试、网络感知、配额预检、大规模删除保护。

> 📌 **定位声明**：BDNSync 是第三方社区插件，与百度官方无任何关联；百度网盘接口（Cookie / 开放平台）随时可能调整，相关功能以实际可用性为准。

## 功能特性

### 核心同步

| 类别          | 能力         | 详情                                        |
| ----------- | ---------- | ----------------------------------------- |
| **双模式连接**   | Cookie 模式  | BDUSS/STOKEN 认证，支持下载、列表、删除操作              |
|             | OpenAPI 模式 | 设备码扫码授权（appKey + secretKey），支持完整的上传/下载/删除 |
| **三向冲突合并**  | 智能合并       | 本地 / 云端 / 上次同步锚点三方对比，文本文件自动 `diff3` 合并    |
|             | 二进制分叉      | 二进制文件冲突时自动保留双方版本（`conflict` 分叉副本）         |
|             | 策略可选       | 智能合并、强制本地/云端优先、始终分叉、每次询问                  |
| **墓碑删除同步**  | 墓碑标记       | 删除操作以「墓碑 + 宽限期」同步，宽限期内可恢复                 |
|             | 宽限期恢复      | 日志墓碑默认 24 小时宽限期，过期后物理清除                   |
| **三种同步模式**  | 实时模式       | 保存文件后 3 秒防抖上传，大文件 10 秒                    |
|             | 自动模式       | 定时轮询（默认 5 分钟），失败指数退避                      |
|             | 手动模式       | 仅通过命令面板或状态栏手动触发                           |
| **整库快照与回滚** | 自动快照       | 强制同步方向前自动生成轻量索引快照点                        |
|             | 一键回滚       | 误删后可从快照列表恢复整库文件状态                         |

### 数据安全

| 类别          | 能力            | 详情                                 |
| ----------- | ------------- | ---------------------------------- |
| **端到端加密**   | AES-256-GCM   | 文件内容在本地加密后再上传，百度网盘无法读取明文           |
|             | PBKDF2-SHA256 | 100,000 轮密钥派生，固定库级 salt + 每文件随机 IV |
|             | 密码强度评估        | 实时反馈密码强度等级（弱/中/强/极强）               |
| **断点续传**    | 分片上传          | 文件按 4MB（可调）分片上传，记录已上行分块            |
|             | 会话持久化         | 崩溃/重启后基于已上行字节数续传，分片 MD5 校验         |
| **版本历史**    | 文件级版本         | 每个文件保留最近 N 个版本（默认 5），按时间倒序         |
|             | 手动恢复          | 通过「版本历史」面板恢复任意历史版本                 |
| **大规模删除保护** | 阈值检测          | 单次同步删除数 ≥ 50 且占比过半时弹窗确认            |
|             | 异常检测          | 云端整树为空却要删本地时强制拦截                   |

## 系统架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        Obsidian Plugin                          │
├─────────────┬─────────────┬──────────────┬──────────────────────┤
│   UI 层     │  命令层     │   设置层     │     实验功能层       │
│  StatusBar  │  Commands   │  SettingTab  │  MediaBridge       │
│  Modals     │  Ribbon     │  Onboarding  │  Backlinks         │
│  Views      │             │              │  Offline Pin       │
├─────────────┴─────────────┴──────────────┴──────────────────────┤
│                         业务逻辑层                                │
│  SyncEngine  │  ConflictResolver  │  RetryQueue  │  DirtySet   │
├─────────────────────────────────────────────────────────────────┤
│                         数据访问层                                │
│  BaiduAdapter  │  LocalStore  │  FileWatcher  │  StreamServer   │
├─────────────────────────────────────────────────────────────────┤
│                         核心能力层                                │
│  BaiduApi  │  Encryptor  │  Logger  │  MD5 │  diff3 │ PathFilter  │
├─────────────────────────────────────────────────────────────────┤
│                         外部依赖                                  │
│  百度网盘 API（Cookie / OpenAPI）  │  Web Crypto API  │ Obsidian API │
└─────────────────────────────────────────────────────────────────┘
```

### 核心组件说明

- **SyncEngine**：同步引擎核心，负责三向对比、决策矩阵、冲突解决、快照生成
- **ConflictResolver**：冲突解决器，实现智能合并、强制策略和分叉保留
- **BaiduApi**：百度网盘 HTTP API 封装，支持双模式认证、限流、重试
- **BaiduAdapter**：百度网盘适配器，统一本地与云端的数据读写接口
- **Encryptor**：AES-256-GCM 端到端加密，PBKDF2 密钥派生
- **LocalStore**：本地索引/快照/会话持久化
- **FileWatcher**：文件变更监听，防抖与风暴检测
- **RetryQueue**：失败重试队列，指数退避持久化
- **DirtySet**：脏路径集合，跨批次累积待同步文件

## 安装

### 普通用户

BDNSync 通过 GitHub Releases 分发，无需从源码构建：

1. 访问本仓库 **[Releases](../../releases)** 页面
2. 下载最新 Release 中的三个插件文件：`manifest.json`、`main.js`、`styles.css`
3. 放入 vault 目录下的 `.obsidian/plugins/bdnsync/`
4. 在 Obsidian 设置 → 第三方插件中启用 **BDNSync**

插件包仅含三个文件：

```
bdnsync/
├── manifest.json
├── main.js
└── styles.css
```

### 从源码构建（开发者）

```bash
git clone https://github.com/yx811/Obsidian-BDN-Sync.git
cd Obsidian-BDN-Sync
npm install
npm run build    # 类型检查 + 生产构建
npm test         # 运行单元测试
npm run lint     # 代码规范检查
```

构建产物为 `main.js` / `styles.css`，可直接部署到 vault 或打包为 Release。

一键部署到本地 vault：

```bash
NODE_VAULT="/path/to/your/Obsidian Vault" npm run deploy
```

## 快速开始

### 第一步：配置连接

进入 Obsidian 设置 → BDNSync → 连接配置：

**Cookie 模式（推荐新手）**

1. 用浏览器登录 <https://pan.baidu.com>
2. 按 F12 打开开发者工具 → Network 面板
3. 刷新页面，找到任意请求的 Cookie 头，复制完整 Cookie 字符串
4. 粘贴到 BDNSync 的 Cookie 输入框
5. 点击「测试连接」验证

**OpenAPI 模式（推荐需要上传的用户）**

1. 访问 <https://pan.open.baidu.com> 创建应用
2. 选择「网页应用」类型，获取 AppKey 和 SecretKey
3. 在「安全设置」中添加回调地址（如 `http://localhost/callback`）
4. 在「接口权限」中勾选「网盘基础服务」和「网盘登录」
5. 将 AppKey 和 SecretKey 填入 BDNSync 设置
6. 点击「设备码授权」，用百度网盘 App 扫描二维码

### 第二步：选择同步模式

| 模式 | 适用场景    | 说明           |
| -- | ------- | ------------ |
| 实时 | 单设备频繁编辑 | 保存后 3 秒自动同步  |
| 自动 | 多设备协作   | 按间隔定时轮询同步    |
| 手动 | 谨慎操作    | 通过命令或状态栏手动触发 |

### 第三步：首次同步

首次同步时会弹出选择对话框：

- **合并**：三向对比智能合并（推荐）
- **云端覆盖本地**：以云端为真相
- **本地覆盖云端**：以本地为真相

选择后 BDNSync 开始同步。

### 第四步：日常使用

- 编辑笔记后自动同步（实时模式）
- 通过命令面板（Ctrl/Cmd+P）可手动触发同步
- 点击状态栏图标查看同步状态和冲突

## 使用指南

### 连接配置详解

#### Cookie 模式

Cookie 模式通过浏览器 Cookie 认证，配置简单但**不支持上传**。

支持的操作：下载、列表、删除

获取 Cookie 步骤：

1. 打开 Chrome/Edge 浏览器，登录 <https://pan.baidu.com>
2. 按 F12 打开开发者工具，切换到 Network 标签
3. 刷新页面，在请求列表中点击任意一个请求
4. 在 Headers 中找到 `Cookie` 字段，复制完整值
5. 粘贴到 BDNSync 设置的 Cookie 输入框

> 💡 Cookie 必须包含 `BDUSS` 和 `STOKEN` 字段，仅复制 BDUSS 可能导致部分功能异常（如配额查询失败）。

#### OpenAPI 模式

OpenAPI 模式通过百度开放平台 OAuth 授权，支持完整的双向同步。

前置条件：

- 访问 <https://pan.open.baidu.com> 注册开发者账号
- 创建「网页应用」类型的应用
- 完成应用配置：

```
安全设置 → OAuth 授权回调页：http://localhost/callback
接口权限 → 勾选：网盘基础服务、网盘登录
```

授权流程：

1. 在 BDNSync 设置中填入 AppKey 和 SecretKey
2. 点击「设备码授权」
3. 使用百度网盘 App 扫描显示的二维码
4. 在 App 中确认授权
5. BDNSync 自动获取 access_token 和 refresh_token

> 💡 access_token 有效期通常为 30 天，过期后 refresh_token 可自动续期。如果自动刷新失败，需要重新完成设备码授权。

### 同步模式详解

#### 实时模式（realtime）

```
文件修改 → 3 秒防抖 → quickSync（仅上传变更文件）
```

- 单文件编辑后 3 秒自动上传
- 大文件（>10MB）延长至 10 秒
- 批量变更（>200 个文件）自动降级为完整同步
- 引擎忙时变更进入脏集合，同步结束后补齐

#### 自动模式（auto）

```
定时轮询 → 5 分钟间隔 → fullSync（全量对比）
```

- 默认 5 分钟间隔，可调范围 1-60 分钟
- 失败后指数退避（1分钟 → 5分钟 → 15分钟）
- 连续 3 次失败后给出低频友好提示

#### 手动模式（manual）

```
用户触发 → fullSync（全量对比）
```

- 通过命令面板「立即同步」触发
- 可配合「同步预览」功能查看计划后确认执行

### 冲突处理

当三方对比检测到冲突时：

1. **智能合并**（默认）：
   - 文本文件：使用 `diff3` 三方合并算法
   - 二进制文件：保留双方版本（创建 `.conflict-<timestamp>` 副本）
2. **冲突策略**：
   - `smart-merge`：智能合并（推荐）
   - `force-local`：强制本地版本覆盖
   - `force-remote`：强制云端版本覆盖
   - `always-fork`：始终保留双版本
   - `ask-me`：每次冲突打开面板手动处理
3. **冲突面板**：
   - 命令「BDNSync: 打开冲突处理面板」
   - 可选择单个冲突的处理策略
   - 支持批量解决所有冲突

### 网盘孤儿备份清理

命令「BDNSync: 扫描并清理网盘备份」：

- 识别父目录下形如 `vault名_YYYYMMDD_HHMMSS[_YYYYMMDD_HHMMSS...]` 的疑似孤儿备份目录——这些目录**通常不是当前 BDNSync 写入**，可能来自旧版本残留 / 网盘 Web 端重命名 / 其它同步工具并发写入。
- **严格安全模型**：默认不递归、严格规则匹配、零自动删除——所有删除都需你在弹窗中逐项勾选并二次确认。
- 候选按风险分级（≥2 段时间戳段叠加 = 高，1 段 = 中），默认勾选高风险项；提供「全选 / 清除选择」批量操作，勾选即时同步底部「删除选中 (N)」按钮状态。
- 删除失败时显示**完整绝对路径与 errno 诊断**，并提供「重试失败项」与「复制失败清单到剪贴板」；弹窗内附「为什么会有这些孤儿」来源说明与预防建议。
- 测量（列出子项）失败时显式标「测量失败」，避免与「真为空」混淆而误删。

#### 深度扫描（v1.0.2+）

> 突破「仅扫描父目录一层」的限制：支持递归进入所有子目录做全量扫描，精确识别三类孤儿，并提供可配置的深度、忽略规则与资源上限。

- **三类孤儿候选**：
  - `backup-dir`（备份目录）：名称匹配 `vault名_时间戳段` 的疑似孤儿备份，风险按时间戳段数分级。
  - `orphan-file`（孤儿文件）：vault 内、不在当前同步索引（LocalIndex）中的文件——无关联引用、无归属的残留数据。
  - `orphan-dir`（孤儿目录）：vault 内空目录，或目录内所有文件也都属孤儿——无归属的残留目录。
  - 安全默认：仅 `backup-dir`（风险 ≥1）会被预勾选；`orphan-file` / `orphan-dir` 默认**不勾选**，需你显式确认，最大限度降低误删。
- **扫描范围（可配置）**：`parent-only`（仅父目录一层，最保守）/ `scoped`（父目录 + vault 顶层）/ `full-vault`（递归进入 vault 全部子树，默认）。
- **可配置深度与忽略**：`maxDepth` 限制递归层数；`extraIgnoreGlobs` 追加 glob 忽略规则（如缓存/缩略图目录）；`.bdnsync*`、`.bdnsync-base*`、`.bdnsync-merge-draft*`、`.bdnsync-backup*` 基础设施目录始终排除。
- **清理前预览清单**：扫描完成后弹窗先展示完整候选清单（含类型 / 路径 / 大小 / 风险 / 来源说明），支持「复制预览清单到剪贴板」导出复核；确认删除前不会触碰任何文件。
- **安全回收 / 永久删除**：可选「送回收站」（默认，百度网盘 deleteFiles 即进回收站，可后台恢复）/「永久删除」。当前百度开放平台无「跳过回收站」接口，若 deleter 未实现 `deleteFilesPermanent`，会**自动降级为送回收站**并显式告警，绝不静默丢失。
- **资源占用控制**：`maxNodes` / `maxBytes` 双预算上限 + `concurrency` 并发池；超出预算即截断（`truncated` 标记），避免大库扫描耗尽配额或卡死。

> **预防性巡检**：开启「检测疑似孤儿目录」后，每次同步结束以及插件启动时（24 小时限频）都会扫描父目录；若短时间内新增 ≥ 3 个孤儿，会弹一条常驻 Notice 提示，可能是多工具并发写入冲突。

## 同步机制

### 三向对比决策矩阵

BDNSync 的核心是三向对比决策矩阵，对比以下三个版本：

- **L**（Local）：本地 vault 中的文件状态
- **R**（Remote）：云端网盘中的文件状态
- **S**（Sync）：上次同步成功时的锚点状态

| 场景     | L    | R    | S    | 决策            | 说明      |
| ------ | ---- | ---- | ---- | ------------- | ------- |
| 无变更    | ✓    | ✓    | ✓    | skip          | 三端一致，跳过 |
| 本地新增   | ✓    | ✗    | ✗    | upload        | 上传本地文件  |
| 云端新增   | ✗    | ✓    | ✗    | download      | 下载云端文件  |
| 本地修改   | ✓    | ✓    | ✓(旧) | upload        | 上传本地修改  |
| 云端修改   | ✓    | ✓    | ✓(旧) | download      | 下载云端修改  |
| 双方修改   | ✓(新) | ✓(新) | ✓(旧) | conflict      | 触发冲突处理  |
| 本地删除   | ✗    | ✓    | ✓    | delete-remote | 删除云端文件  |
| 云端删除   | ✓    | ✗    | ✓    | delete-local  | 删除本地文件  |
| 双方删除   | ✗    | ✗    | ✓    | skip          | 两端都删，跳过 |
| 本地删云端改 | ✗    | ✓(新) | ✓    | conflict      | 删除-修改冲突 |
| 云端删本地改 | ✓(新) | ✗    | ✓    | conflict      | 修改-删除冲突 |

### 决策流程图

```
本地扫描 → 云端列表 → 三向对比
                              ↓
                         生成同步计划 (actions[])
                              ↓
                    ┌─────────┼──────────┐
                    ↓         ↓          ↓
                 下载执行  上传执行    冲突解决
                    ↓         ↓          ↓
                    └─────────┼──────────┘
                              ↓
                         提交远程索引
                              ↓
                         保存本地索引
                              ↓
                      更新版本历史/快照
                              ↓
                         清理缓存/备份
```

### 墓碑与宽限期机制

```
删除操作 → 标记墓碑 (deleted: true)
              ↓
         同步到对端（对端也标记墓碑）
              ↓
         宽限期内可恢复（本地/云端仍保留）
              ↓
         宽限期过期 → 物理清除
```

### 断点续传机制

```
文件上传开始
    ↓
分片 1 上传完成 → 持久化会话
分片 2 上传完成 → 持久化会话
...
    ↓（网络中断/崩溃）
    ↓
恢复后读取 transfer-state.json
    ↓
校验已上传分片 MD5
    ↓
从断点继续上传剩余分片
    ↓
全部完成 → 合并分片
```

### 远程索引分片机制

为支持万级文件的大型知识库，BDNSync 采用分片方案管理远程索引：

```
.bdnsync/
├── index.json              # 清单（元信息 + 分片列表）
├── shards/
│   ├── shard-0.json        # 分片：{ files: Record<string, FileState> }
│   ├── shard-1.json
│   └── ...
```

- **清单轻量化**：`index.json` 仅包含元信息和分片文件名列表，体积与文件总数无关
- **按需加载**：仅同步必要的分片，避免单 JSON 过大
- **向后兼容**：文件数较少时自动使用内联模式（`files` 直接内联）
- **乐观锁**：`syncVersion` 在清单上 +1，CAS 语义防止并发写入冲突

### 乐观锁与并发控制

```
设备 A 读取远程索引（syncVersion=5）
    ↓
执行本地变更
    ↓
提交前检查：远程 syncVersion 是否仍为 5？
    ├── 是 → 写入成功，syncVersion +1（=6）
    └── 否 → 并发冲突，重新拉取索引后重试
```

- **CAS 语义**：每次写入前校验版本号，防止多设备并发覆盖
- **自动重试**：检测到版本冲突时自动重新拉取索引并重试
- **分片独立**：分片不参与版本号，仅清单维护全局版本

## 安全说明

> 更完整的审计与处置记录见 [安全审计报告](docs/reviews/security-audit-report.md)。

### 凭据保护

- **信封加密**：BDUSS/STOKEN/Token 等敏感字段落盘前经 AES-GCM 信封加密（见 `src/security/secrets.ts`）
- **主密钥隔离**：加密主密钥存放于 `localStorage`（不随 vault 同步、不进入 `data.json`），换设备/清缓存后凭据自动失效并要求重新授权
- **自动脱敏**：所有日志与错误提示中的令牌/Cookie 自动脱敏（`access_token=<redacted>`）
- **导入安全**：设置导入采用白名单 + 类型校验，防止 Mass-Assignment 攻击；导出时自动脱敏凭证字段

### 端到端加密

- **算法**：AES-256-GCM（Authenticated Encryption）
- **密钥派生**：PBKDF2-SHA256，100,000 轮迭代
- **Salt 策略**：库级固定 salt（持久化到设置）+ 每文件随机 IV
- **密码强度**：实时评估密码强度等级（0-4 级：未设置/弱/中/强/极强），弱密码给出警告
- **向后兼容**：旧版「每文件随机 salt」密文可正常解密

#### 加密文件格式

```
┌──────────┬──────────┬──────────┬────────────────────┐
│  Magic   │   Salt   │    IV    │  Ciphertext + Tag  │
│  (8B)    │  (16B)   │  (12B)   │     (变长)         │
├──────────┼──────────┼──────────┼────────────────────┤
│ BDNSYNC1 │ 随机 salt│ 随机 IV  │ AES-256-GCM 密文   │
│  标识头  │ 库级固定 │ 每文件   │ + 16B GCM Tag      │
│          │ (持久化) │ 随机生成 │                    │
└──────────┴──────────┴──────────┴────────────────────┘
```

> Magic 头用于快速识别加密文件，解密时会校验 Magic 一致性，不匹配则抛出错误。

### 大规模删除保护

- **阈值检测**：单次同步删除数 ≥ 50 且占比过半时弹窗确认
- **异常检测**：云端整树为空却要删本地时强制拦截
- **风暴保护**：批量变更（>200 文件）自动降级为完整同步
- **实时保护**：实时同步路径同样受大规模删除保护

### 数据隐私

- **无数据收集**：本插件不收集、不上传任何使用数据到第三方服务器
- **仅存必要数据**：插件仅存储同步所需的索引、配置和日志
- **日志持久化**：日志存储在 vault 的 `.obsidian/plugins/bdnsync/` 目录下
- **本地处理**：所有加密、解密、合并操作均在本地完成

### 性能优化

- **哈希缓存（LRU）**：文件内容 MD5 缓存上限 5000 条目，命中时跳过整文件读取与哈希计算
- **带宽节流**：可配置的上传/下载带宽上限，采用「余数累积」算法平滑吞吐，避免小分片抖动
- **批量备份缓冲**：覆盖/删除前的备份元数据在内存累积，同步结束后统一提交，IO 从 O(N) 降到 O(1)
- **并发控制**：上传/下载并发数可独立配置（默认 3），平衡速度与网盘 QPS 限制
- **智能降级**：批量变更（>200 文件）自动从增量同步降级为全量对比，确保数据一致性

### 鲁棒性特性

- **文件锁重试**：检测到 Windows EBUSY/EPERM、macOS 锁等瞬时错误时，指数退避重试最多 3 次
- **密钥缓存**：PBKDF2 派生密钥缓存上限 32 个，避免重复计算 100,000 轮哈希
- **网络感知**：网络断开自动暂停同步，恢复后自动补同步
- **配额预检**：同步前预检网盘空间，超过 95% 时警告，容量不足时暂停
- **崩溃恢复**：断点续传会话持久化到磁盘，重启后校验分片 MD5 恢复上传
- **大规模删除保护**：删除数 ≥ 50 且占比过半时强制确认，防止误操作

## 代码文件说明

下面按职责划分说明主要源码文件，便于贡献者快速定位。

### 入口与编排

- **`src/main.ts`** — 插件生命周期（`onload`/`onunload`）、命令与 Ribbon 注册、文件变更事件路由、同步触发（`syncNow` / `quickSync` / `stormSync`）、自动调度、重试队列与脏集合装配、状态栏/面板入口。是所有模块的总装点。
- **`src/types.ts`** — 全局类型：`AuthMode`、`SyncMode`、`ConflictStrategy`、`FileState`、`RemoteIndex`（含分片与乐观锁 `syncVersion`）、`BDNSyncSettings` 等。

### 百度网盘接入

- **`src/baidu/api.ts`** — 百度网盘原始 HTTP API 封装。双模式（Cookie / OpenAPI）认证；设备码 OAuth 授权与自动刷新；QPS 节流、瞬态错误指数退避（`transientRetry`）；统一错误类型 `BaiduApiError` 与 errno 映射；凭据脱敏 `redactSecrets`；上传三步（precreate → superfile2 分片 → create）；目录/删除/移动/分享/搜索。
- **`src/baidu/adapter.ts`** — 适配器层，向上屏蔽"本地 vs 云端"差异，统一文件读写、索引读写、加解密接入（`Encryptor`）。

### 同步引擎

- **`src/sync/engine.ts`** — 核心同步引擎：`fullSync`（全量对账）/ `quickSync`（增量）/ 三向对比决策矩阵、同步计划生成、冲突触发、快照生成、远程索引读写与乐观锁提交。
- **`src/sync/conflict-resolver.ts`** — 冲突解决：文本 `diff3` 智能合并、二进制分叉、强制方向与询问策略。
- **`src/sync/dirty-set.ts`** — 脏路径集合，跨批次累积待同步文件，避免增量退化成全量。
- **`src/sync/retry-queue.ts`** — 失败重试队列，指数退避、瞬态失败持久化（`transfer-state.json`）、后台轮询 flush。

### 数据安全

- **`src/crypto/encryption.ts`** — `Encryptor`：AES-256-GCM 端到端加密，PBKDF2-SHA256 密钥派生（100k 轮），库级 salt + 每文件随机 IV，密钥缓存。
- **`src/security/secrets.ts`** — 凭据信封加密：落盘前对 BDUSS/STOKEN/Token/secretKey/加密密码做 AES-GCM 加密（`enc::` 前缀），主密钥存 `localStorage`，解密失败安全回退。

### 存储与监听

- **`src/storage/local-store.ts`** — 本地持久化：索引、快照、会话、重试状态、日志，含分片加载与损坏容错。
- **`src/watcher/file-watcher.ts`** — 文件变更监听：防抖（实时模式 3s）、风暴检测（>阈值降级全量）、rename 配对。

### UI 层

- **`src/ui/*.ts`** — 状态栏、设置页、各类弹窗（首发同步/冲突/统计/快照/版本历史/远程占用）、网盘浏览器、文件预览、媒体播放器、首次引导、连接配置弹窗等。
- **`src/ui/views/*.ts`** — 以 Obsidian `ItemView` 标签页形式承载网盘浏览器、同步日志、文件预览。
- **`src/stream-server.ts`** — 本地流式代理（**桌面端**）：启动 `127.0.0.1` HTTP 服务，把百度直链响应流式 pipe 给浏览器，实现免落盘边下边播；移动端无 Node 运行时时自动回退为下载模式。

### 工具与实验功能

- **`src/util/diff3.ts`** — 三方合并算法。
- **`src/util/md5.ts`** — MD5（同步/异步），用于内容哈希与分片校验。
- **`src/util/misc.ts`** — `PathFilter`（glob 排除）、`formatBytes`、`genDeviceId`、`sleep` 等通用工具。
- **`src/util/logger.ts`** — 持久化订阅式日志器，含墓碑清理、筛选、导出。
- **`src/lab/*.ts`** — MediaBridge（`bdn://` 直嵌）、Backlinks（反向引用）、Offline Pin（离线收藏）、Health Score（同步健康分）。

## 已知限制

- **桌面端优先**：流式预览/边下边播依赖 Node `http`/`https`/`net`（`src/stream-server.ts`），仅桌面端可用；移动端会自动回退为"下载后再打开"模式。因此 `manifest.json` 中的 `isDesktopOnly` 当前为 `false`（插件可加载），但**流式代理类功能在移动端不可用**。若希望纯移动端体验一致，建议后续将 `isDesktopOnly` 设为 `true` 或在移动端屏蔽相关入口。
- **Cookie 模式不支持上传**：百度网盘 Web 端点权限限制，Cookie 模式仅能下载/列表/删除；需要上传请使用 OpenAPI 设备码授权。
- **依赖百度接口稳定性**：百度网盘 Cookie / 开放平台接口可能调整，部分功能以实际可用性为准。

## 常见问题

### Q: Cookie 模式和 OpenAPI 模式有什么区别？

| 对比项   | Cookie 模式     | OpenAPI 模式                          |
| ----- | ------------- | ----------------------------------- |
| 认证方式  | 浏览器 Cookie    | OAuth 设备码                           |
| 配置难度  | 简单            | 中等                                  |
| 上传支持  | ❌             | ✅                                   |
| 下载支持  | ✅             | ✅                                   |
| 列表/删除 | ✅             | ✅                                   |
| 清晰度   | 取决于 Cookie 权限 | 取决于 OAuth 权限                        |
| 有效期   | Cookie 过期即失效  | access_token 30天 + refresh_token 续期 |

**建议**：需要双向同步的用户使用 OpenAPI 模式；仅需下载的用户使用 Cookie 模式。

### Q: 同步时出现冲突怎么办？

BDNSync 默认使用智能合并策略：

1. 文本文件：`diff3` 三方合并算法自动尝试合并
2. 二进制文件：保留双方版本（创建分叉副本）
3. 可在设置中切换策略，或改为「每次询问」手动处理
4. 通过「冲突处理面板」可批量解决未解决的冲突

### Q: 如何备份重要数据？

建议：

1. 使用 BDNSync 的**整库快照**功能，在强制同步前自动生成快照点
2. 定期执行本地备份（U盘、外部硬盘等）
3. 不要将 BDNSync 作为唯一的数据保护手段
4. 开启版本历史功能，每个文件保留最近 5 个版本

### Q: 忘记加密密码怎么办？

端到端加密的密码无法找回。忘记密码将导致云端密文永久无法解密。

**请务必**：

- 将密码保存在安全的密码管理器中
- 在所有设备上使用相同密码
- 启用加密前先确认密码可记住

### Q: 支持哪些 Obsidian 版本？

BDNSync 支持 Obsidian 1.13.7 及以上版本。插件本身可安装于桌面端与移动端，但流式代理等依赖 Node 运行时的功能仅在桌面端可用（详见[已知限制](#已知限制)）。

### Q: 实时同步和自动同步有什么区别？

| 对比项  | 实时同步             | 自动同步           |
| ---- | ---------------- | -------------- |
| 触发方式 | 文件保存事件           | 定时器轮询          |
| 延迟   | 3 秒              | 5 分钟（默认）       |
| 同步范围 | 仅变更文件（quickSync） | 全量对比（fullSync） |
| 网络占用 | 低                | 中等             |
| 可靠性  | 依赖事件触发           | 定时兜底           |

### Q: 百度网盘容量不足怎么办？

1. 在设置中查看「远程存储与分析 → 占用明细」了解空间分布
2. 清理不必要的文件释放空间
3. 购买更大容量的网盘套餐
4. BDNSync 会在配额超过 95% 时警告，并在容量不足时暂停同步

### Q: 如何迁移到新设备？

1. 在旧设备上导出设置（设置页 → 维护 → 导出配置）
2. 在新设备上安装 BDNSync
3. 导入配置（设置页 → 维护 → 导入配置）
4. 注意：**不要迁移 deviceId**（保持新设备生成的唯一标识）
5. 重新完成 OpenAPI 授权（如果使用）
6. 首次同步选择「云端覆盖本地」或「合并」

### Q: 日志存储在哪里？

日志文件位于 vault 的：

```
.obsidian/plugins/bdnsync/sync-logs.json
```

可在设置中配置：

- 记录级别（debug/info/warn/error）
- 保留天数（超过天数的日志墓碑清理）
- 容量上限（环形缓冲，超出按时间最旧淘汰）
